# StrokeGuard 初赛演示与设备维护程序设计

日期：2026-07-13  
状态：已确认，待实施

## 1. 目标

将 `StrokeGuard-Demo.exe` 从完整 PC 开发工具精简为面向初赛的双模式程序：

1. 默认“实时演示”模式只展示 VPS 上真实设备 `sg-0001` 的监控数据和豆包建议。
2. 独立“设备维护”模式负责部署 YAML、COM 连接、ESP-IDF 编译、擦除、烧录及串口日志监视。
3. 不生成或回退到模拟数据；网络、会话或设备异常必须明确显示真实状态。
4. 原始音视频始终只在设备本地处理，演示程序和云端只读取结构化数值与建议文本。

## 2. 运行边界

- 目标硬件为 ESP32-S3-WROOM-1 N16R8。
- PC 不是镜端运行依赖，只承担演示监控和开发维护。
- VPS/FastAPI/EMQX 仍是远程监控数据来源；S3 风险等级为权威结果。
- EXE 不内置 ESP-IDF 工具链。维护模式检测并调用本机 ESP-IDF v5.5.3，默认路径为 `E:\esp\v5.5.3\esp-idf`，并允许用户选择其他有效路径。
- 首期默认设备为 `sg-0001`，实现保留更换设备 ID 的配置能力，不增加多用户和设备所有权系统。

## 3. 信息架构

### 3.1 实时演示

实时演示是启动后的默认页面，只保留评委需要观察的内容：

- 产品名称、当前设备 ID、云端状态和设备在线状态。
- F、S、T、E、CSI、最终评分。
- S3 风险等级、否决项和结构化原因。
- 最新豆包建议、建议来源和完成时间。
- 隐私说明和医疗免责声明。
- 进入设备维护页的次要入口。

删除模拟源、FPS、原始帧、算法后端、数据记录、开发日志和重复的成功提示。未接入模态显示“未接入”，不得显示默认分数。断网时保留最后一次数据但显著标注“非实时”，并显示最后更新时间；不得继续动画或伪装为在线。

状态必须区分：

- `云端不可达`：HTTP 请求无法到达 VPS。
- `登录失效`：服务器返回未授权，要求重新登录。
- `设备离线`：云端可达，但最近 30 秒没有目标设备上行。
- `数据未接入`：设备在线，但具体模态值为 `null`。

### 3.2 登录

程序启动后由用户输入 VPS 演示账号和密码。凭据只用于建立当前进程的会话，不写入 EXE、YAML、日志或本地长期存储。登录成功后自动绑定默认设备 `sg-0001`。

### 3.3 设备维护

设备维护页与演示页视觉和职责隔离，包含：

- 自动扫描可用 COM 口、刷新和手动选择。
- 芯片探测，拒绝将 N16R8 配置无提示地用于不匹配目标。
- 打开、编辑和校验部署 YAML。
- ESP-IDF 路径和版本检查。
- 分阶段操作：配置校验、编译、擦除、烧录、串口监视。
- 可停止的串口监视和脱敏日志。

擦除是破坏性操作，只有用户明确勾选“允许擦除目标设备”并再次确认目标 COM 口后才执行。编译、擦除或烧录期间禁用冲突操作。退出程序时必须终止子进程并释放串口。

## 4. 部署 YAML

部署 YAML 不包含用户医学档案，结构如下：

```yaml
schema_version: 1

device:
  id: sg-0001
  management_token: ${STROKEGUARD_MANAGER_TOKEN}

wifi:
  ssid: ${STROKEGUARD_WIFI_SSID}
  password: ${STROKEGUARD_WIFI_PASSWORD}

mqtt:
  uri: mqtt://example:1883
  username: ${STROKEGUARD_MQTT_USERNAME}
  password: ${STROKEGUARD_MQTT_PASSWORD}

hardware:
  camera:
    model: GC2145
    enabled: false
    pins: {}
  microphone:
    model: NMO432
    enabled: false
    sample_rate: 16000
    channel: left
    pins: {}
```

真实密钥由进程环境变量或被 Git 忽略的本地 `.env` 提供。界面默认遮挡敏感字段，日志统一替换为 `***`。模板、测试夹具和发布包不得包含真实凭据。

校验规则：

- `schema_version` 必须为 `1`。
- `device.id` 必须符合现有 MQTT 设备 ID 约束且不能为空。
- Wi-Fi SSID、MQTT URI 和必需凭据必须解析成功后才能编译。
- 摄像头仅支持声明 `GC2145`，麦克风仅支持声明 `NMO432`。
- NMO432 固定使用 3.3V 供电和 I2S 接口；YAML 必须声明 `SCK/BCLK`、`WS/LRCLK`、`SD/DIN` GPIO 以及与 `L/R` 接法一致的左右声道。`VDD` 接 3.3V，`GND` 接公共地，不允许接 5V。
- 启用 GC2145 或 NMO432 时必须提供固件 Kconfig 要求的全部 GPIO；缺失、重复、越界或保留引脚均阻止编译。
- 本阶段不猜测任何 GPIO，也不自动启用未确认硬件。

## 5. ESP-IDF 集成

维护程序通过受控子进程调用 ESP-IDF，不拼接未经校验的自由文本命令。预期阶段为：

1. 检测 IDF v5.5.3、Python 环境、工程目录和目标 COM 口。
2. 将已校验 YAML 转换为本次构建使用的本地配置；配置文件必须被 Git 忽略。
3. 执行 `idf.py set-target esp32s3` 和 `idf.py build`。
4. 可选执行 `idf.py -p <PORT> erase-flash`。
5. 执行 `idf.py -p <PORT> flash`。
6. 执行 `idf.py -p <PORT> monitor` 或等价串口监视，并展示经过脱敏的输出。

YAML 到 Kconfig 的映射必须使用明确字段白名单。禁止把密码放入命令行参数或 UI 错误弹窗；生成配置的落盘位置和清理策略需由实现测试覆盖。

## 6. 错误处理

- 每个阶段返回独立状态：待执行、运行中、成功、失败、已取消。
- 失败时展示阶段、简明原因和可操作建议，完整脱敏输出留在维护日志中。
- COM 被占用时不自动杀死其他程序，提示用户关闭占用者。
- 烧录失败后不宣称设备可用；只有启动日志和 VPS 上行均通过才显示“验收通过”。
- VPS 不可用不影响设备维护；ESP-IDF 不可用不影响远程演示。

## 7. 视觉原则

- 实时演示采用安静、医疗监护风格，评分数字清晰，状态灯尺寸克制。
- 主要页面不使用开发术语和大段使用说明。
- 维护页使用步骤状态和结构化表单，不暴露无意义的底层反馈。
- 所有按钮文案表示明确命令；危险操作采用警示色和二次确认。
- 适配 1366x768 及更高 Windows 桌面分辨率，文本不得重叠或截断。

## 8. 测试与验收

### 自动测试

- VPS 客户端：登录、会话失效、超时、设备离线和 `null` 模态。
- YAML：正常配置、缺字段、未知字段、环境变量缺失、GPIO 冲突和凭据脱敏。
- IDF 任务：命令白名单、阶段状态、取消、非零退出码和串口释放。
- UI：无模拟入口、默认真实设备、离线状态、危险操作确认和退出清理。
- 发布：EXE 可启动，发布包不含 `.env`、本地 YAML、`sdkconfig`、日志或密钥。

### 人工验收

1. 启动 EXE，登录后自动连接 `sg-0001`。
2. S3 在线时显示真实 CSI、融合等级和豆包建议。
3. F/S/T/E 为 `null` 时显示“未接入”，不生成数字。
4. 断开 VPS 网络后明确显示“云端不可达”和最后更新时间。
5. 选择 COM 口，加载有效 YAML，完成编译和烧录。
6. 未确认擦除、引脚缺失或板型不匹配时操作被阻止。
7. 串口日志不出现 Wi-Fi、MQTT 或管理 Token 明文。
8. 烧录后设备独立运行，并恢复 VPS 实时上行。

## 9. 非目标

- 不实现模拟数据或答辩假数据。
- 不把 ESP-IDF、训练权重或原始音视频打包进 EXE。
- 不实现 OTA、设备远程控制、多用户账号、历史曲线或医学档案编辑。
- 不宣称尚未完成的 GC2145/NMO432 驱动或 F/S/T/E 真机能力已经可用。
