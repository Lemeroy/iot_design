# 卒中卫士独立镜端架构设计

日期：2026-07-11
状态：已确认，作为后续实现的权威架构基线

## 1. 结论

卒中卫士采用“ESP32-S3 独立闭环、PC 可选管理、云端增强建议”的架构。

- ESP32-S3-WROOM-1 N16R8 是运行主体。采集、五模态评分、确定性融合、离线告警、TFT 显示、声光播报和 MQTT 上报均在镜端完成。
- PC 不参与日常判定，只在同一局域网内提供状态监控、参数标定、模型更新、日志查看和人工开启的校准预览。
- 云端只接收数值评分和用户档案，负责时序存储、预警推送和大模型建议；原始音视频、图像特征、MFCC 与关键点不得上传云端。
- 大模型输出只能补充说明和建议，不能改变、降低或撤销镜端确定性告警。
- 断网或 PC 关闭时，镜端检测、融合、显示和声光告警必须照常工作。

本架构替代此前“PC 承担视觉/语音推理并向云端上传”的运行方式。现有 PC 感知代码保留为算法原型、数据标定工具和边缘模型的对照实现，不再是产品运行依赖。

## 2. 方案取舍

### 2.1 采用方案：完全独立边缘闭环

ESP32-S3 执行轻量模型和融合规则，PC 仅作管理端。该方案最符合竞赛对 ESP32 边缘 AI、多源融合、云端大模型上下行和独立产品形态的要求，也满足离线告警与隐私约束。

### 2.2 未采用：PC 主推理

PC 可运行 YOLOv8、68 点关键点和较大语音模型，开发速度较快，但镜子不能独立工作，削弱边缘计算展示，也让 USB/PC 成为运行单点故障。

### 2.3 未采用：云端主推理

云端模型能力更强，但需要上传原始音视频，违反隐私铁律，并使告警依赖公网时延与可用性。

## 3. 系统边界

```text
GC2145 摄像头 ─┐
INMP441 麦克风 ─┼─> ESP32-S3 边缘感知 ─> 五模态融合 ─> 本地告警/显示/播报
Wi-Fi CSI ──────┘           │                    │
                            │                    └─> MQTT 数值 uplink
                            │                              │
                            └─> 局域网管理接口              v
                                   │              EMQX -> FastAPI -> InfluxDB
                                   v                         │
                            可选 PC 管理端                    └─> 豆包/OpenAI 兼容大模型
                                                               │
                                                               v
                                                    MQTT 建议文本 downlink
```

物理感知来源是三类：摄像头、麦克风和 Wi-Fi CSI。五个评分模态由其派生：

| 模态 | 来源 | 镜端职责 | 医学边界 |
| --- | --- | --- | --- |
| F 面部 | GC2145 | 人脸定位、少量关键点或轻量对称模型、口角偏移 | 对应 FAST 的 Face 风险提示 |
| S 言语 | INMP441 | 16 kHz 采样、MFCC、INT8 清晰度分类 | 对应 FAST 的 Speech 风险提示 |
| T 舌偏 | GC2145 | 引导伸舌、ROI 与几何/小模型评分 | 仅作中医望诊辅助，不单项诊断或否决 |
| E 眼动 | GC2145 | 眼区 ROI、左右运动一致性评分 | 借鉴 BE-FAST 的 Eyes，不能替代视力检查 |
| B 稳定性 | Wi-Fi CSI | 滑窗稳定性特征和 0-100 评分 | 借鉴 BE-FAST 的 Balance，只反映镜前稳定性趋势 |

Arm 因镜子视野限制不单独测量。若未来补全 Arm，应通过可穿戴或外部设备另立设计，不增加到当前镜端 BOM。

## 4. ESP32-S3 软件架构

### 4.1 FreeRTOS 任务

| 任务 | 输入 | 输出 | 失败处理 |
| --- | --- | --- | --- |
| `sensor_camera` | GC2145 帧 | 共享图像缓冲区 | 标记 F/T/E 不可用，不阻断其他模态 |
| `sensor_audio` | INMP441 PCM | 音频环形缓冲区 | 标记 S 不可用并提示重新采集 |
| `sensor_csi` | Wi-Fi CSI 包 | B 分与质量指标 | 样本不足时 B 为不可用 |
| `inference_visual` | 图像帧 | F/T/E 分、质量、辅助量 | 超时丢弃旧帧，不累积排队 |
| `inference_speech` | PCM 窗口 | S 分、`p_clear`、质量 | 无有效语音时不出分 |
| `fusion` | 最新有效模态快照 | `final`、`level`、`reasons`、`veto_by` | 输入权重不足时输出 `insufficient` |
| `alert_ui` | 融合事件、云端建议 | TFT/LED/蜂鸣器/语音状态 | 本地固定告警文案优先于云端建议 |
| `mqtt` | 融合事件 | 数值 uplink、建议 downlink | 指数退避重连，不阻塞本地闭环 |
| `manager` | 局域网 API/WS | 状态、受限配置、校准流 | 未认证或非校准态拒绝原始流 |
| `supervisor` | 心跳与资源水位 | 故障状态、任务恢复 | 记录故障并进入可解释降级状态 |

任务间使用有界队列或“最新值”快照。视觉和语音推理不得形成无界积压；过期输入直接丢弃。告警、融合和 UI 的优先级高于 MQTT 与校准预览。

### 4.2 模型与运行时约束

- PC 上现有 YOLOv8、MediaPipe/68 点和 Python CNN 不能原样部署到 ESP32-S3。
- 镜端视觉采用 ESP-DL/ESP-WHO 可支持的轻量检测网络、少量关键点或专用 INT8 对称分类器。GC2145 与所选组件的像素格式兼容性必须在摄像头到货后实测；不预先编造驱动能力或分辨率。
- 语音采用本地 MFCC 加 INT8 CNN。当前没有训练权重，开发阶段只能验证数据通路和占位模型接口，不能声称具备医学识别精度。
- T/E 使用 ROI 几何或小型 INT8 模型，不引入通用大模型。
- 模型、输入尺寸、峰值 PSRAM、单次推理时延和热稳定性均作为设备实测指标。固件必须在模型加载失败时继续运行其他模态。
- N16R8 的 16 MB Flash 与 8 MB PSRAM 用于双 OTA 分区、模型分区、帧缓冲和运行堆；具体分区尺寸在模型文件确定后通过构建产物校验。

## 5. 评分与确定性决策

所有模态分数范围为 0-100，分数越高表示当前表现越接近基线稳定状态。每个分数同时携带有效性、质量和采样时间；陈旧或质量不足的数据不参与融合。

```text
final = 0.35 * face
      + 0.25 * speech
      + 0.20 * tongue
      + 0.12 * eye
      + 0.08 * csi
```

- 缺失模态按现有规则对剩余权重归一化；可用原始权重之和小于 `0.50` 时为 `insufficient`。
- `face <= 30` 或口角偏移绝对值 `>= 20°` 时直接 `danger`。
- `speech <= 35` 且 `p_clear < 0.4` 时直接 `danger`。
- 无否决时，`final >= 70` 为 `normal`，`40 <= final < 70` 为 `warning`，`final < 40` 为 `danger`。
- 结果原为 `normal` 时，`eye < 30` 或 `csi < 30` 提级为 `warning`。
- 舌偏只参与辅助加权，不设置单项否决。

这些阈值是项目规则基线，不代表临床诊断阈值。M6 必须在合规标注数据上报告灵敏度、特异度、混淆矩阵和 K 折结果后再决定是否调整；不得预先编造精度。

## 6. 云端 MQTT 契约

主题保持不变：

```text
strokeguard/<device_id>/uplink
strokeguard/<device_id>/downlink
```

### 6.1 S3 到云端：只允许结构化数值

```json
{
  "schema_version": 1,
  "scores": {
    "face": 82,
    "speech": 76,
    "tongue": 80,
    "eye": 74,
    "csi": 68,
    "final": 78
  },
  "level": "normal",
  "profile": {
    "age": 68,
    "gender": "other",
    "conditions": [],
    "meds": [],
    "stroke_history": false
  },
  "reasons": [],
  "veto_by": [],
  "device_id": "sg-0001",
  "ts": 1783760000,
  "seq": 42
}
```

`jpeg`、音频、MFCC、关键点、图像 ROI 和可还原生物特征的数据均不属于该契约，云端必须拒绝这些字段。主题中的设备 ID 必须与载荷中的 `device_id` 一致。

### 6.2 云端到 S3：仅展示/播报建议

```json
{
  "schema_version": 1,
  "level": "normal",
  "advice_text": "请继续观察，如出现面部歪斜或言语不清请立即拨打120。",
  "ts": 1783760002,
  "source": "ep-..."
}
```

- S3 只接受有长度上限、合法 UTF-8、级别有效且未过期的建议文本。
- `level` 不得覆盖本地级别；显示时以本地较高风险级别为准。
- 下行不提供 shell、GPIO 任意控制、模型参数任意写入或复杂指令执行。
- 开发联调可在受控网络使用 MQTT 1883；比赛交付和长期公网运行要求 TLS 8883、设备级账号和 ACL，并关闭公网匿名访问。

## 7. PC 局域网管理契约

PC 通过设备局域网 IP 访问版本化接口：

```text
GET  /api/v1/status
GET  /api/v1/config
PUT  /api/v1/config
POST /api/v1/calibration/start
POST /api/v1/calibration/stop
POST /api/v1/update/model
POST /api/v1/update/firmware
WS   /api/v1/telemetry
WS   /api/v1/calibration
```

### 7.1 职责边界

- `status`：固件/模型版本、各模态分数和质量、融合级别、网络状态、内存水位、最近错误。
- `config`：只允许白名单内且有上下界的采样参数、设备档案、显示设置和云端地址。配置包含版本号与 CRC32，写入 NVS 前完整校验，失败时保留上一版本。发布固件中的融合权重、单项否决和危险阈值为只读；研究固件调整这些参数时必须物理授权，并持续显示“研究模式”。
- `telemetry`：发送结构化状态和调试指标，不发送原始音视频。
- `calibration`：仅在人工授权会话内发送受限图像/音频校准流，格式由握手协商；默认不录制。
- `update`：只接受匹配 N16R8 目标、版本可验证且签名有效的模型包或固件包。写入非活动分区，完整性校验通过后才切换；启动自检失败时自动回滚。更新操作需要管理令牌和镜端物理确认。
- PC 不向 S3 注入最终分数，不参与线上融合，也不代理 MQTT。

### 7.2 校准隐私与认证

校准模式默认关闭，并同时满足以下条件才可启动：

1. PC 使用预置管理令牌认证；令牌不通过 MQTT 或日志回显。
2. 用户在镜端长按物理校准键，打开一个 60 秒授权窗口。
3. PC 在授权窗口内请求启动，会话最长 10 分钟，到时自动停止。
4. TFT 全程显示明显的“局域网校准中”状态，LED 使用独立状态提示。
5. 校准流只能发往当前已认证客户端；断连、锁屏、超时或再次按键立即停止。
6. PC 默认不保存原始数据。用户明确开启录制时，只保存到本机加密目录并记录同意事件；任何情况下都不得转发云端。

USB-CDC 继续作为烧录、恢复和底层调试接口，并保留既有长度加 CRC16 的帧协议；它不再是正常运行数据链路。

## 8. 状态、降级与错误处理

镜端状态机为：

```text
boot -> self_test -> ready -> measuring -> normal|warning|danger|insufficient
                              \-> calibration (人工授权、限时)
```

- 云端断开：本地继续判定；MQTT 采用有上限的指数退避，仅在 RAM 中保留有限条最新结构化事件，恢复后按序补发。重启后不承诺恢复未上传历史，以避免高频写 Flash。
- 大模型失败：显示本地固定安全文案，不影响告警级别。
- 单传感器失败：相关模态标记不可用；可用权重不足则显示 `insufficient`，不得把缺失数据当作正常。
- 资源不足：优先停校准预览和非关键遥测，再降低采样频率；不得停用本地告警任务。
- 时间未同步：使用单调序号并标记时钟未同步；获得 SNTP 时间后再发送绝对时间。
- `danger`：立即执行本地红灯、蜂鸣和就医提醒，无需等待 MQTT 或大模型返回。

## 9. 医学与内容安全

【医学顾问 Dr.Chen】统一表述如下：

- 产品是脑卒中风险提示和就医提醒工具，不是诊断设备，不能替代医生评估。
- FAST 的 F、S 为核心映射；E、B 仅借鉴 BE-FAST；T 是辅助参考；Arm 未独立测量。
- 当设备提示危险，或本人/家属观察到突发面部歪斜、言语不清、单侧肢体无力、视物异常、平衡障碍、意识改变等症状时，应立即拨打 120，不等待设备复测或云端建议。
- 大模型不得给出诊断结论、虚构药物、擅自建议停药/换药，也不得使用安慰性措辞降低紧急程度。
- “4.5 小时”等治疗时间窗不能被描述成等待窗口；具体治疗适应证由医院专业人员判断。

## 11. 实施里程碑

| 阶段 | 交付 | 通过标准 |
| --- | --- | --- |
| E1 独立链路 | S3 直连 MQTT、NVS 配置、镜端融合、离线告警、建议下行接口 | PC 和公网断开时可产生本地融合与告警；联网后只上传数值并接收建议 |
| E2 面部边缘模型 | GC2145 采集、人脸检测、F 分和口角辅助量 | 真机持续运行，输出含质量标志的 F 分；无脸时不误填正常分 |
| E3 言语边缘模型 | INMP441、MFCC、INT8 CNN、S 分 | 16 kHz 通路稳定；无有效语音时为不可用；模型版本可追踪 |
| E4 完整五模态 | T/E/CSI、时间对齐、否决与融合、TFT/声光/播报 | 五模态可独立故障降级；danger 不依赖 PC/云端触发 |
| E5 PC 管理端 | LAN 发现、监控、受限配置、校准预览、模型更新 | 默认无原始流；物理授权、认证、指示、超时和停止条件全部生效 |
| E6 评测交付 | 训练/量化、OTA、TLS、HIL、K 折和安装包 | 给出可复现评测报告、固件资源报告、联调清单和回滚验证 |

当前已有资产：CSI 端侧评分、USB-CDC 帧协议、确定性融合 C 实现、PC 五模态算法原型与 PyQt5 UI、云端 EMQX/InfluxDB/FastAPI/豆包链路。尚未完成的是 ESP32 直连 MQTT、视觉/语音边缘模型及其真实权重、局域网管理接口和整机外设联调。

## 12. 测试与验收

【测试工程师 Quinn】按四层验收：

1. 纯函数测试：融合边界、缺失模态、否决规则、JSON 契约、CRC、配置上下界和版本迁移。
2. 组件测试：摄像头断连、麦克风静音、CSI 样本不足、MQTT 断网、LLM 超时、NVS 损坏和低内存。
3. 硬件在环：N16R8 长时间运行、外设逐项接入、反复断网/重启、校准模式超时、OTA 成功与回滚。时延、内存和稳定性数字均标注“实测”，不使用估算冒充结果。
4. 算法评测：使用合规且去标识的数据，受试者维度切分训练/验证集，避免同一人的样本泄漏到不同折；报告灵敏度、特异度、阳性/阴性预测值、混淆矩阵、K 折均值与离散程度，并单列不同环境、年龄和设备条件下的局限。

竞赛演示最小验收链路为：真机采集至少两类物理来源并形成五模态中的可用评分，S3 本地完成融合与告警，S3 直接向云端上传数值，云端大模型返回建议文本，镜端显示或播报该文本；拔掉 PC 后整条链路仍可运行。
